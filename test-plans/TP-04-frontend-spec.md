# Тест-план: Frontend — портал оператора й черга рецензента

**Джерело:** `docs/04-frontend-spec.md` · **Дата:** 2026-10-22 · **Версія:** 1.0

## 1. Обсяг тестування
**Входить:** логін/реєстрація оператора й сесія, реєстри пілотів і ЛА, форма заявки й «Check before submitting», «My requests» і деталі заявки, черга рецензента (approve/reject), контракт `data-testid`, відсутність префільтрації пікерів
**Не входить:** візуальний дизайн (явно мінімальний), логіка гейтів на бекенді (`06`), підвищення `authorisation_level` (адмін-дія поза UI), автотести

## 4. Критерії початку й завершення
**Початок:** фронтенд і API розгорнуто на стенді, доступна Supabase Auth, заведено зони й тестових операторів
**Завершення:** усі кейси «Високий» виконано й пройдено, немає відкритих дефектів Critical/High, відкриті питання зафіксовано

## 5. Оточення та тестові дані
- Стенд із фронтендом, API і Supabase Auth; актуальні Chrome/Firefox
- Ролі: 2 оператори (`L1` і вище, свої пілоти/ЛА), рецензент з `X-Reviewer-Id` у шапці
- Дані: активна/неактивна зона, ЛА різних вагових класів, заявки в усіх state
- Заявки, що гарантовано падають на кожному з гейтів `PILOT`/`AIRCRAFT`/`ZONE`/`TIME_WINDOW`

## 6. Ризики
| Ризик | Як знижуємо |
|---|---|
| Немає повного списку `data-testid` — нема з чим звіряти | Зняти інвентар елементів, погодити як еталон |
| Перехід на сесію: залишки «ручного» operator ID в UI | Окремі перевірки приховування/видалення старих елементів |
| Рецензент без логіна — будь-який ID у шапці дає доступ | Негативні кейси з порожнім/чужим/некоректним ID |
| Поведінку UI для `SUSPENDED` оператора не визначено | Фіксувати фактичну поведінку, не вважати еталоном |

## 7. Відкриті питання
- Q4 (`05`) — код/тіло відповіді для `SUSPENDED` не визначені → невідомо, що UI показує на create/submit
- Q5 (`05`) — посилання `ZC-2026.1 §4` для неактивної зони не підтверджено → текст rule reference в UI
- Нове — немає повного переліку `data-testid`; незрозуміло, які імена вважати еталонними
- Нове — чи доступна «Check before submitting» до збереження чернетки (validate потребує `{id}`)
- Нове — напрям сортування черги за замовчуванням і набір state у фільтрі «My requests»
- Нове — валідацію `X-Reviewer-Id` в UI (формат, порожнє значення) не описано
