# Тест-план: SkyPermit — вся спецификация

**Источник:** `docs/*` · **Дата:** 2026-10-22 · **Версия:** 1.0

## 1. Объём тестирования
**Входит:** модель данных и ограничения, жизненный цикл `FlightRequest`, API 1–16 + auth, 4 гейта и бизнес-правила, UI оператора и ревьюера
**Не входит:** производительность и нагрузка, создание/правка `Zone` (вне приложения), правила из `CR-1` и `OH-1` v1.4, автотесты

## 2. Подход к тестированию
| Вид | Техника | Источник |
|---|---|---|
| Переходы состояний | таблица переходов, все пары (from, action) | `02#Request Lifecycle` |
| API-контракт | коды `400/401/403/404/409/422`, тело `422` | `03#Error semantics` |
| Бизнес-правила | граничные значения + таблица решений по гейтам | `06#1. The four gates` |
| Безопасность | роль × сессия × чужой ресурс | `03#Authentication & authorisation` |
| Данные | классы эквивалентности, unique/FK/лимиты | `01#Entities` |
| UI | сценарии по экранам, контракт `data-testid` | `04#Two contracts to hold exactly` |

## 4. Критерии начала и окончания
**Начало:** стенд с API, UI и Supabase Auth; засеяны 6 зон из `06#4`; тестовые данные готовы
**Окончание:** все пункты «Высокий» пройдены; нет открытых дефектов Critical/High; открытые вопросы зафиксированы

## 5. Окружение и тестовые данные
- Стенд API `/api/v1` + фронтенд + Supabase; управляемые часы/даты для границ времени
- Операторы `L1`/`L2`/`L3` (+ `SUSPENDED`), ревьюер с `X-Reviewer-Id`
- Пилоты всех `rating`, `certified_on` на границе 18 мес; ЛА 900/3500/12000/30000/30001 г
- Заявки во всех state; окна на границах curfew (`A-7` vs `ZC-2026.1`) и с касанием по времени

## 6. Риски
| Риск | Как снижаем |
|---|---|
| Противоречия в доках по коду ответа (overlap, `SUSPENDED`) | Фиксировать факт, эскалировать до утверждения кейсов |
| Curfew в local time, хранение в UTC — ошибки конвертации | Кейсы через полночь и поминутно по краям окна |
| `SUBMITTED` транзиентен — отмену из него не воспроизвести | Пометить кейс как непроверяемый через API |
| Устаревшие значения (`OH-1` v1.4: 24 мес, 4000 г) | Явные граничные кейсы по текущим порогам |

## 7. Открытые вопросы
- Q4 (`05#1`) — код/тело для `SUSPENDED` не определены, а `03#Error semantics` уже называет `403` → блокирует кейсы create/submit/approve
- Q5 (`05#2`) — `ZC-2026.1 §4` для неактивной зоны не подтверждена → ожидаемый `rule_reference`
- Новый — overlap: `409` (`03#Error semantics`) или `422 TIME_WINDOW` (`06#1.4`)? Плюс `02` относит его к `AIRCRAFT`/`TIME_WINDOW`
- Новый — `validate` останавливается на первом провале (`03`), а UI ревьюера показывает «все четыре» результата (`04`)
- Новый — эндпоинт `complete` (`02`) отсутствует в списке API `03`
- Новый — lead time 6 ч при `validate`: от какого момента считать (`06#1.4` говорит «submission»)
- Новый — ответ `submit` при провале гейта: `422` (`08` pipeline) или `200` с `REJECTED` (`08` alt submit)?
