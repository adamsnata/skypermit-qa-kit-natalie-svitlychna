# Тест-план: SkyPermit — уся специфікація

**Джерело:** `docs/*` · **Дата:** 2026-10-22 · **Версія:** 1.0

## 1. Обсяг тестування
**Входить:** модель даних і обмеження, життєвий цикл `FlightRequest`, API 1–16 + auth, 4 гейти й бізнес-правила, UI оператора й рецензента
**Не входить:** продуктивність і навантаження, створення/редагування `Zone` (поза застосунком), правила з `CR-1` і `OH-1` v1.4, автотести

## 4. Критерії початку й завершення
**Початок:** стенд з API, UI і Supabase Auth; засіяно 6 зон з `06#4`; тестові дані готові
**Завершення:** усі пункти «Високий» пройдено; немає відкритих дефектів Critical/High; відкриті питання зафіксовано

## 5. Оточення та тестові дані
- Стенд API `/api/v1` + фронтенд + Supabase; керований годинник/дати для меж часу
- Оператори `L1`/`L2`/`L3` (+ `SUSPENDED`), рецензент з `X-Reviewer-Id`
- Пілоти всіх `rating`, `certified_on` на межі 18 міс; ЛА 900/3500/12000/30000/30001 г
- Заявки в усіх state; вікна на межах curfew (`A-7` vs `ZC-2026.1`) і з дотиком за часом

## 6. Ризики
| Ризик | Як знижуємо |
|---|---|
| Суперечності в документах щодо коду відповіді (overlap, `SUSPENDED`) | Фіксувати факт, ескалювати до затвердження кейсів |
| Curfew у local time, зберігання в UTC — помилки конвертації | Кейси через північ і похвилинно на краях вікна |
| `SUBMITTED` транзієнтний — скасування з нього не відтворити | Позначити кейс як неперевірюваний через API |
| Застарілі значення (`OH-1` v1.4: 24 міс, 4000 г) | Явні граничні кейси за поточними порогами |

## 7. Відкриті питання
- Q4 (`05#1`) — код/тіло для `SUSPENDED` не визначені, а `03#Error semantics` уже називає `403` → блокує кейси create/submit/approve
- Q5 (`05#2`) — `ZC-2026.1 §4` для неактивної зони не підтверджено → очікуваний `rule_reference`
- Нове — overlap: `409` (`03#Error semantics`) чи `422 TIME_WINDOW` (`06#1.4`)? Плюс `02` відносить його до `AIRCRAFT`/`TIME_WINDOW`
- Нове — `validate` зупиняється на першому провалі (`03`), а UI рецензента показує «всі чотири» результати (`04`)
- Нове — ендпоінт `complete` (`02`) відсутній у списку API `03`
- Нове — lead time 6 год під час `validate`: від якого моменту рахувати (`06#1.4` каже «submission»)
- Нове — відповідь `submit` у разі провалу гейту: `422` (`08` pipeline) чи `200` з `REJECTED` (`08` alt submit)?
