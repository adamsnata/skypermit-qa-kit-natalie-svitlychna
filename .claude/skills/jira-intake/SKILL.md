# Intake задачі Jira

Прочитати задачу Jira за ключем і віддати її як один JSON-обʼєкт. Скіл нічого не оцінює й не перевіряє: лише дістає дані з задачі.

## Обмеження

- **Лише читання.** Дозволені інструменти: `getJiraIssue`, `getJiraIssueRemoteIssueLinks`. Не викликай жодних create/edit/comment/transition/worklog/link-інструментів Atlassian. Файли не створюй і не змінюй.
- Confluence **не відкривай**: `confluence_url` береться лише з самої задачі.
- Нічого не вигадуй і не добудовуй. Чого в задачі немає, того немає й у JSON (`null` або порожній список) з поясненням у `notes`.
- Відповідай українською; значення полів, що цитуються із задачі, залишай дослівно.

## Джерело

Jira, cloudId `04cfe3ba-ca1f-4d3c-8ff3-b67f1f3c5083` (site `skypermitdocs.atlassian.net`).

## Алгоритм

1. **Вхід.** Аргумент має бути ключем задачі формату `ABC-123`. Якщо це довільний текст, повідом про це й зупинись.
2. **Задача.** Виклич `getJiraIssue` з `cloudId` вище, `issueIdOrKey` = аргумент, `fields: ["summary","description","labels","issuetype","status"]`, `responseContentFormat: markdown`. Якщо задачі немає або доступу немає, поверни JSON з `key` і поясненням у `notes`, інші поля `null` / `[]`. Не повторюй запит навмання.
3. **Поля.**
   - `key`: ключ задачі з відповіді Jira.
   - `title`: `summary` дослівно.
   - `check_type`: лише з `labels`. Враховуються тільки мітки `ui` та `api` (без урахування регістру), усі інші мітки (напр. `ws3`) ігноруються. Є лише `ui` → `"ui"`. Є лише `api` → `"api"`. Є обидві або жодної → `null`, а причину запиши в `notes`. Ніколи не виводь тип із заголовка, опису, типу задачі чи компонентів.
   - `acceptance_criteria`: список рядків. Знайди в описі розділ Acceptance criteria (або «Критерії приймання» / «AC») і винеси кожен пункт окремим елементом у порядку задачі, дослівно, без переформулювання та без обʼєднання чи розбиття. Якщо розділу немає, то `[]` і запис у `notes`.
   - `confluence_url`: посилання на Confluence (`*.atlassian.net/wiki/...`) з опису задачі. Якщо в описі його немає, виклич `getJiraIssueRemoteIssueLinks` і візьми Confluence-посилання звідти. Якщо посилань кілька, у `confluence_url` постав те, що прямо названо специфікацією в описі, або перше за порядком, а решту перелічи в `notes`. Якщо немає жодного, то `null`. Згадка Confluence текстом, без справжнього URL (напр. "Confluence → простір SkyPermit → сторінка «06 — …»"), це не посилання: `confluence_url` = `null`, а в `notes` додай рядок "Посилання на Confluence лише текстом: «<дослівна цитата з опису>»".
   - `notes`: список коротких рядків про все, що викликає сумнів: відсутня або неоднозначна мітка, відсутній розділ AC, кілька Confluence-посилань, незвичний формат опису. Якщо зауважень немає, то `[]`.
4. **Вивід** у форматі нижче.

## Формат виводу

Лише один блок JSON, без пояснень до і після нього:

```json
{
  "key": "SKY-1",
  "title": "…",
  "check_type": "ui",
  "acceptance_criteria": [
    "…",
    "…"
  ],
  "confluence_url": "https://skypermitdocs.atlassian.net/wiki/spaces/SD/pages/…",
  "notes": []
}
```

Типи полів: `key` і `title` рядки, `check_type` одне з `"ui"`, `"api"`, `null`, `acceptance_criteria` і `notes` масиви рядків, `confluence_url` рядок або `null`.
