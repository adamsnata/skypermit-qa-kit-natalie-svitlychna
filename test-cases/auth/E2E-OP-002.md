# E2E-OP-002: Вход через /login с верными email и паролем → оператор залогинен

**Doc ref:** `04-frontend-spec.md#Operator portal`, `04-frontend-spec.md#Two contracts to hold exactly`, `03-api-contract.md#Authentication & authorisation`, `app/login/page.tsx`, `components/AppHeader.tsx`
**Role(s):** Operator (`ACTIVE`, до входа — без сессии)
**Preconditions:**
- Зарегистрирован оператор с email `e2e-op-002@example.com`, паролем `Sky-Permit-2026` и `status` = `ACTIVE`.
- Пользователь не залогинен: в шапке видны `operator-login-link` и `operator-register-link`.

**Steps:**
1. Открыть `/login` (ссылка `operator-login-link` в шапке).
2. Заполнить `operator-login-email-input` = `e2e-op-002@example.com`, `operator-login-password-input` = `Sky-Permit-2026`.
3. Нажать `operator-login-submit-button`.

**Expected result:** Оператор залогинен: в шапке отображаются `operator-session-info` и `operator-logout-button`, а `operator-login-link` и `operator-register-link` больше не отображаются; `operator-login-error` не появляется.

**Rationale:** Позитивный сценарий (happy path) входа: по `04#Operator portal` у оператора есть страница `/login`, по `03#Authentication & authorisation` `POST /auth/login` принимает email + password и устанавливает session cookie. Признак залогиненного состояния — набор `data-testid` из `04#Two contracts to hold exactly`. Взят оператор со статусом `ACTIVE`: поведение для `SUSPENDED` не определено (`05-open-questions.md#1`, Q4) — это отдельный кейс с `TODO`. Детали реализации, которых нет в docs: после входа код перенаправляет на `/operator/pilots`, а `operator-session-info` показывает `legal_name` — в ожидаемый результат не включены.
