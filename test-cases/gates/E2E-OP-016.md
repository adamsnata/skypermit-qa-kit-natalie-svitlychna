# E2E-OP-016: «Check before submitting» із провалом AIRCRAFT (смуга C3, KBP-CTR-3) → заявка лишається у стані DRAFT

**Doc ref:** `SD/04 — Frontend Scope#Operator portal`, `SD/03 — API Contract#Flight requests`, `SD/02 — Request Lifecycle#States`, `SD/06 — Business Rules#1.2 AIRCRAFT`, `components/FlightRequestPanel.tsx`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 2 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `15000` (смуга `C3`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `100`, `window_start` = 22:00 місцевого часу зони дати, що настає через 7 днів, `window_end` = 22:45 того ж дня (45 хвилин; поза curfew 23:00–05:00).
- Браузер працює в часовому поясі `Europe/Kyiv`.

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** `flight-request-detail-state` показує `DRAFT`.

**Rationale:** Задача: SKY-3, AC 5. `validate` ніколи не змінює стан (`SD/04#Operator portal`, `SD/03#Flight requests`), на відміну від `submit`, який при провалі гейта переводить заявку в `REJECTED` (`SD/02`). Перевірка стану після провалу `AIRCRAFT` показує, що `validate` не діє як `submit`. Ознака стану — `data-testid` `flight-request-detail-state` із коду.
