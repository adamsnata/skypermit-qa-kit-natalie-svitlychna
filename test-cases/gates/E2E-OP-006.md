# E2E-OP-006: «Check before submitting» для вікна 22:00–22:45 у KBP-CTR-3 (поза curfew 23:00–05:00, усі інші умови валідні) → гейт TIME_WINDOW = pass

**Doc ref:** `SD/06 — Business Rules#1.4 TIME_WINDOW`, `SD/06 — Business Rules#4. Zone catalogue`, `SD/04 — Frontend Scope#Operator portal`, `components/GateResultsPanel.tsx`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 2 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `2000` (смуга `C1`, дозволена в `KBP-CTR-3`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `80`, `window_start` = 22:00 місцевого часу зони дати, що настає через 7 днів, `window_end` = 22:45 того ж дня (45 хвилин). Інших `APPROVED`/`UNDER_REVIEW` заявок на цей ЛА немає.
- Браузер працює в часовому поясі `Europe/Kyiv`.

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** Картка `flight-request-gate-result-TIME_WINDOW` показує `pass` (атрибут `data-gate-status` = `PASS`).

**Rationale:** Еквівалентний валідний клас, що доводить: для `KBP-CTR-3` діє curfew з `A-7` §1 (23:00–05:00), а не загальне значення `ZC-2026.1` 22:00–06:00 — за загальним значенням вікно 22:00–22:45 теж було б у curfew (`SD/06#1.4`, таблиця curfew по зонах; AC SKY-1 №5). Решта умов валідна (лід-тайм 7 днів, тривалість 45 хв у межах 15–240, висота 80 м ≤ 120 м, `L2`, смуга `C1` ∈ C0–C2, перетину з іншими заявками немає).
