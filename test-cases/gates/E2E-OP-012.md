# E2E-OP-012: Провал AIRCRAFT для ЛА смуги C3 у KBP-CTR-3 → у картці гейта показано посилання на правило ZC-2026.1 §2

**Doc ref:** `SD/06 — Business Rules#6. rule_reference values`, `SD/04 — Frontend Scope#Operator portal`, `SD/07 — Clarifications#1`, `components/GateResultsPanel.tsx`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 2 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `15000` (смуга `C3`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `100`, `window_start` = 22:00 місцевого часу зони дати, що настає через 7 днів, `window_end` = 22:45 того ж дня (45 хвилин; поза curfew 23:00–05:00).
- Браузер працює в часовому поясі `Europe/Kyiv`.

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** TODO: уточнити за вимогами (чи має картка `flight-request-gate-result-AIRCRAFT` у результаті перевірки показувати `rule_reference` `ZC-2026.1 §2`; `SD/04#Operator portal` описує лише per-gate pass/fail)

**Rationale:** Задача: SKY-3, AC 2 (частина 2b, у `doc_check` — «не описано»). `SD/06#6` задає `rule_reference` = `ZC-2026.1 §2` для `AIRCRAFT` у `422`, але `SD/04#Operator portal` не вимагає показувати його в результаті перевірки (згадано лише для деталей заявки). Очікувану поведінку не вигадуємо: відкрите питання для аналітика. Розбіжність із кодом: `components/GateResultsPanel.tsx` — картка у стані `FAIL` виводить `message` і `rule_reference` в елементі `.sp-gate__rule` (без `data-testid`); у docs такої вимоги немає.
