# E2E-OP-007: Провал TIME_WINDOW через curfew у KBP-CTR-3 → у картці гейта показано rule_reference `A-7 §1`

**Doc ref:** `SD/06 — Business Rules#6. rule_reference values`, `SD/06 — Business Rules#1.4 TIME_WINDOW`, `SD/04 — Frontend Scope#Operator portal`, `components/GateResultsPanel.tsx`, `SD/03 — API Contract#The 422 body`, `SD/03 — API Contract#Gate pipeline (shared by submit and validate)`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 2 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `2500` (смуга `C1`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `90`, `window_start` = 23:30 місцевого часу зони дати, що настає через 10 днів, `window_end` = 00:15 наступної доби (45 хвилин; усе вікно всередині curfew).
- Браузер працює в часовому поясі `Europe/Kyiv`.
- У браузері відкрито DevTools → Network (запис мережі ввімкнено до кроку 2).

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** У картці `flight-request-gate-result-TIME_WINDOW` відображається `rule_reference` = `A-7 §1`; рядка `ZC-2026.1 §3` у картці немає; у Network відповідь на `POST /api/v1/flight-requests/<id>/validate` має код `422`, а в її тілі `failing_gate` = `TIME_WINDOW` і `rule_reference` = `A-7 §1`.

**Rationale:** AC SKY-1 №2: причина відмови має цитувати поправку, а не базовий каталог. За `SD/06#6` для curfew у `KBP-CTR-3`/`ODS-CTR-5` `rule_reference` = `A-7 §1`, для інших зон — `ZC-2026.1 §3`; `A-7` §4 каже, що поправка діє там, де документи розходяться. Текст `message` у docs не зафіксований, тому в очікуваний результат не включено. Часовий пояс зони в docs не зазначено — `TODO: уточнити за вимогами (часовий пояс зони й те, у якому поясі вводиться datetime-local)`; код приймає `Europe/Kyiv` (`lib/curfew.ts`).
