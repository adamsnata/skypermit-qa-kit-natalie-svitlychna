# E2E-OP-004: «Check before submitting» для вікна 22:30–23:15 у KBP-CTR-3 (кінець вікна заходить у curfew) → гейт TIME_WINDOW = fail

**Doc ref:** `SD/06 — Business Rules#1.4 TIME_WINDOW`, `SD/06 — Business Rules#4. Zone catalogue`, `SD/04 — Frontend Scope#Operator portal`, `components/GateResultsPanel.tsx`, `lib/curfew.ts`, `SD/03 — API Contract#The 422 body`, `SD/03 — API Contract#Gate pipeline (shared by submit and validate)`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 3 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `1000` (смуга `C1`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `60`, `window_start` = 22:30 місцевого часу зони дати, що настає через 8 днів, `window_end` = 23:15 того ж дня (45 хвилин; 30 хв поза curfew, 15 хв — у curfew 23:00–05:00).
- Браузер працює в часовому поясі `Europe/Kyiv`.
- У браузері відкрито DevTools → Network (запис мережі ввімкнено до кроку 2).

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** Картка `flight-request-gate-result-TIME_WINDOW` показує `fail` (атрибут `data-gate-status` = `FAIL`); у Network відповідь на `POST /api/v1/flight-requests/<id>/validate` має код `422`, а в її тілі `failing_gate` = `TIME_WINDOW` і `rule_reference` = `A-7 §1`.

**Rationale:** Гранично-подібний клас: вікно лише частково потрапляє в curfew (початок до 23:00, кінець після 23:00). За `SD/06#1.4` curfew перевіряється поминутно по всьому вікну, а не лише по кінцях, а AC SKY-1 №1 вимагає fail, якщо «будь-яка частина» вікна потрапляє в 23:00–05:00. Решта умов валідна (лід-тайм 8 днів, тривалість 45 хв, висота 60 м ≤ 120 м, смуга `C1` ∈ C0–C2, `L2`).
