# E2E-OP-013: Провал AIRCRAFT для ЛА смуги C3 у KBP-CTR-3 → гейт PILOT (R_ADVANCED у CONTROLLED) показано як pass

**Doc ref:** `SD/06 — Business Rules#Evaluation order`, `SD/06 — Business Rules#1.1 PILOT`, `SD/06 — Business Rules#4. Zone catalogue`, `SD/04 — Frontend Scope#Operator portal`, `components/GateResultsPanel.tsx`
**Role(s):** Operator (L2, ACTIVE) — залогінений
**Preconditions:**
- Оператор з `authorisation_level` = `L2` і `status` = `ACTIVE` залогінений.
- Пілот цього оператора: `rating` = `R_ADVANCED`, `certified_on` = дата за 2 місяці до `window_start`.
- ЛА цього оператора: `mtom_grams` = `15000` (смуга `C3`).
- Заявка у `DRAFT` для цього пілота й ЛА: `zone_code` = `KBP-CTR-3`, `requested_altitude_metres` = `100`, `window_start` = 22:00 місцевого часу зони дати, що настає через 7 днів, `window_end` = 22:45 того ж дня (45 хвилин; поза curfew 23:00–05:00).
- Браузер працює в часовому поясі `Europe/Kyiv`.

**Steps:**
1. Відкрити сторінку деталей цієї заявки `/operator/requests/<id>`.
2. Натиснути `flight-request-validate-button`.

**Expected result:** Картка `flight-request-gate-result-PILOT` показує `pass` (атрибут `data-gate-status` = `PASS`).

**Rationale:** Задача: SKY-3, AC 3. Порядок гейтів `PILOT` → `AIRCRAFT` → `ZONE` → `TIME_WINDOW` із зупинкою на першому провалі (`SD/06#Evaluation order`); перший провал — `AIRCRAFT`, тож `PILOT` пройдений. Дані справді проходять `PILOT`: `R_ADVANCED` дозволений у `CONTROLLED` (`KBP-CTR-3`), сертифікація чинна на `window_start` (2 місяці < 18) — `SD/06#1.1`. Примітка про реалізацію: API віддає лише перший провалений гейт, а `PASS` для `PILOT` виводить клієнт (`components/GateResultsPanel.tsx`); це узгоджується з `SD/06#Evaluation order` і `SD/04#Operator portal`.
